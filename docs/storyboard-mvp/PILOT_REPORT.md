## 试用目标与准入条件

目标是让 3～5 位目标用户各自使用一段原创或已获授权的单场景剧本，独立完成：登录 → 创建/选择项目 → 输入并解析 → 选择场景 → 生成 4～8 镜分镜 → 编辑保存 → 重做一镜并采纳/放弃 → 刷新确认 → 复制 Prompt 或导出 Markdown。

开始约访前，产品负责人逐项确认：

- [ ] SB-12 已用受控的真实 provider 完成质量、时延、用量和费用上限记录；结果能通过 `resultRef` 打开 Java 已保存产物。
- [ ] 候选环境已按 `RUNBOOK.md` 的 live 模式预检，三项服务均健康；不使用 fixture、mock 或浏览器内置演示数据。
- [ ] 为每位试用者准备独立账号与组织/项目空间，且浏览器不保留上一位用户的会话。
- [ ] 可选场景含规范场景头，规范化 LF 后不超过 8,000 字符；创作要求不超过 1,000 字符；内容不含未获授权的敏感个人数据。
- [ ] 已向试用者说明录屏/笔记范围与退出方式；记录中使用 `P-01`～`P-05`，不记录密码、JWT、执行令牌、模型密钥或完整私人剧本文本。
- [ ] 产品负责人、观察员和技术值守已确认：观察员只在用户明确卡住、会话安全或服务故障时介入，并按下表记为“协助”。

任一项未满足时，本任务保持“待试用”，只能进行技术演示或预检，不能计入验收用户数。

## 试用脚本

每位用户一次独立会话，建议预留 45 分钟：5 分钟说明、25 分钟自主操作、10 分钟回访、5 分钟记录核对。产品负责人不替用户点击、不讲解操作步骤；只宣读以下开场说明。

> 请用你自己的一个场景，尽量像平时工作一样完成从输入到导出。你可以随时说出困惑或停止操作；我们会记录界面和流程问题，不评价你的创作能力。除非你明确请求帮助或出现安全/服务故障，我们不会代替你操作。

### 观察步骤与计时规则

| 阶段 | 用户任务 | 观察员记录 | 计时边界 |
| --- | --- | --- | --- |
| 0 | 登录并确认可进入项目页 | 是否自行进入；登录/权限错误 | `T0` = 用户首次可操作页面 |
| 1 | 创建项目或选择已有项目，粘贴一个场景并解析 | 是否理解输入约束和场景选择；解析失败 | 操作时间累计 |
| 2 | 选择一个场景、4～8 个镜头和创作要求，点击“生成分镜” | `runId`、目标镜头数、是否重复点击 | `T_generate_click` |
| 3 | 等待生成完成并打开 `resultRef` 指向的保存分镜 | 状态是否可理解；断线/失败/取消；不得以 SSE 文本判定成功 | 模型等待 = `T_result_ready - T_generate_click`；`T_result_ready` 为 Java run 终态完成且页面成功加载详情 |
| 4 | 核对原文，编辑至少一项并保存；任选一镜重做、比较候选后采纳或放弃 | 保存/冲突/提案状态是否理解；保留、修改、重做的镜头号 | 操作时间累计；第二次生成另记等待时间 |
| 5 | 刷新页面，确认已保存内容仍在；复制至少一个 Prompt 或导出 Markdown | 是否实际复制/下载；导出或复制将用于哪一步制作 | `T_export_or_copy`；总历时 = `T_export_or_copy - T0` |
| 6 | 完成回访 | 再次使用意愿及原因；最影响完成任务的问题 | 不计入操作时间 |

“用户操作时间” = 从 `T0` 到 `T_export_or_copy` 的总历时 − 所有模型等待历时 − 观察员/技术人员造成的中断。解析、保存、刷新等非模型等待保留在操作时间内，同时在事件日志中单独标出。未完成会话记录结束时刻、卡点和介入原因，不把缺失数据当成零。

### 结束访谈（逐项询问）

1. 哪些镜头可以原样保留？哪些仅需修改？哪些需要重做？请说出原因。
2. 你是否复制了图像/视频 Prompt 或导出了 Markdown？实际用于或准备用于制作流程的哪一步？
3. 若下周还有同类场景，你会再次使用吗？为什么？
4. 从“最妨碍完成这次任务”角度，排出三个问题；分别说出发生在哪一步和你期望的改进。
