# 小说/剧本自动分镜 Agent 工作台产品文档

## 1. 产品定位

**小说/剧本自动分镜 Agent 工作台** 是一个面向 AI 影视创作的文本转分镜系统。

它不是传统制片管理系统，而是把小说、短剧剧本、影视剧本文本转换成后续可以用于 AI 绘图、AI 视频、导演分镜和镜头设计的结构化内容。

核心链路是：

```text
小说/剧本文本
  -> 场景拆分
  -> 人物/地点/动作/情绪/画面要素提取
  -> 镜头规划
  -> 分镜描述
  -> 图像/视频生成 Prompt
  -> 分镜板展示和导出
```

当前 Java 后端 MVP 先完成前半段：

```text
项目管理
文本版本管理
规则化场景拆分
基础元素提取
Markdown 导出
为后续 Agent 自动分镜预留接口边界
```

后续接入 PI Agent 后，系统才进入真正的“自动分镜生成”阶段。

## 2. 产品目标

这个产品要解决的问题是：用户有一段小说或剧本文本，但不知道如何快速拆成可视化镜头。

产品希望让用户完成：

```text
1. 导入小说或剧本文本
2. 自动拆分为场景
3. 自动识别每个场景中的人物、地点、关键动作和氛围
4. 自动生成镜头列表
5. 为每个镜头生成分镜描述
6. 为每个镜头生成 AI 绘图/视频 Prompt
7. 在前端以分镜板形式查看、调整和导出
```

第一版后端不直接生成最终分镜，而是先打好结构化数据基础。

## 3. 目标用户

### 3.1 AI 影视创作者

他们可能有小说、短剧脚本、剧情大纲，希望快速生成可视化分镜。

典型需求：

```text
粘贴一段文本
快速拆出场景
看到每场戏的视觉重点
生成分镜草稿
拿到 AI 图像/视频 Prompt
```

### 3.2 短剧编导 / 分镜师

他们需要把剧本转成镜头语言，减少手工拆分成本。

典型需求：

```text
按场景查看文本
确认人物和地点
生成镜头列表
调整景别、机位和动作描述
导出分镜表
```

### 3.3 AI 视频工具开发者

这个项目也可以作为简历项目，展示 Java 后端、Agent 架构、剧本文本解析、权限隔离和接口设计能力。

可展示亮点：

```text
Spring Boot 后端
JWT 鉴权
组织级租户隔离
PostgreSQL
剧本文本解析
AgentClient 抽象
自动分镜业务建模
Swagger / Apifox 调试
可扩展到 PI Agent
```

## 4. 典型使用流程

### 4.1 登录

用户先登录系统，获得 Bearer Token。

```text
POST /api/v1/auth/login
```

后续项目、文本、解析结果和未来分镜数据都属于当前登录用户所在组织。

### 4.2 创建作品项目

用户创建一个作品项目，例如：

```text
项目名：雨夜试镜
类型：悬疑短片
描述：根据小说片段生成自动分镜
```

这个项目可以理解为一部小说、短剧、广告片、短片或影视项目的工作空间。

### 4.3 导入小说/剧本文本

用户在项目下保存一个文本版本。

文本来源可以是：

```text
小说章节
短剧剧本
影视剧本
剧情大纲
AI 生成的故事片段
```

当前 MVP 用 JSON 直接保存原始文本；后续可以支持 txt、docx、pdf 或在线文档导入。

### 4.4 自动场景拆分

用户点击“解析”。

当前 MVP 使用 Java 规则解析器：

```text
识别场景头
拆分场景正文
识别内景/外景
识别白天/夜晚
提取地点
提取人物
提取道具、声音和风险提示
```

对于小说文本，后续 Agent 可以进一步处理：

```text
根据段落和语义拆场
识别时间、地点变化
识别人物行动
识别情绪和画面氛围
补充分镜所需视觉信息
```

### 4.5 自动分镜生成

这是产品的核心能力，但不属于当前 Java MVP 的第一步。

未来接入 PI Agent 后，每个场景可以生成多个镜头。

每个镜头可以包含：

```text
镜头序号
景别：远景 / 全景 / 中景 / 近景 / 特写
机位：平视 / 俯拍 / 仰拍 / 跟拍 / 手持
镜头运动：推 / 拉 / 摇 / 移 / 固定
人物动作
画面描述
情绪氛围
AI 图像 Prompt
AI 视频 Prompt
负面 Prompt
```

示例：

```text
场景：旧摄影棚，夜，雨声

镜头 1：
景别：远景
画面：废弃摄影棚外雨水倾泻，霓虹灯在积水中闪烁。
Prompt：cinematic wide shot of an abandoned film studio at night, heavy rain, neon reflections, suspense mood

镜头 2：
景别：近景
画面：收音机突然亮起，旋钮自己转动，发出沙沙声。
Prompt：close-up of an old radio turning on by itself, dim studio light, horror suspense atmosphere
```

### 4.6 分镜板查看与导出

React 前端阶段可以做成工具台：

```text
左侧：项目和文本版本
中间：场景列表
右侧：镜头卡片 / 分镜卡片
底部：Prompt、导出、重新生成
```

可导出：

```text
Markdown 分镜表
Excel 分镜表
PDF 分镜板
JSON 给生成服务
```

## 5. 当前 MVP 范围

当前后端 MVP 是自动分镜系统的基础层，不是最终完整产品。

已经聚焦在：

```text
1. 登录鉴权复用现有 SaaS 后端
2. 作品项目创建、列表、详情
3. 文本版本创建、列表、详情
4. 文本输入校验
5. 规则化场景拆分
6. 场景入库
7. 基础元素提取
8. 重复解析时替换旧结果
9. 解析失败时保留上次成功结果
10. 场景和元素查询
11. Markdown 导出
```

当前 MVP 不做：

```text
React 前端
真正的小说语义拆分
PI Agent 接入
自动生成镜头列表
自动生成 Prompt
分镜卡片编辑
图片生成
视频生成
Excel/PDF 分镜导出
多人协作
```

## 6. 核心数据对象

### 6.1 Project 作品项目

表示一个小说、剧本或短片项目。

```text
项目名
类型
描述
所属组织
创建人
状态
```

### 6.2 Script Version 文本版本

表示某个项目下的一版原始文本。

```text
版本名
原始文件名
原始文本
解析状态
创建时间
```

解析状态：

```text
UPLOADED
ANALYZED
ANALYZE_FAILED
```

### 6.3 Scene 场景

表示从文本中拆出来的一段可视化场景。

```text
场景序号
场景头
内景/外景
地点
白天/夜晚
场景正文
顺序
```

### 6.4 Element 画面/制片元素

表示场景中对分镜有帮助的基础信息。

```text
人物 CHARACTER
地点 LOCATION
道具 PROP
声音 SOUND
风险 RISK
```

这些元素未来会作为 Agent 生成分镜的上下文。

### 6.5 Shot 镜头

后续阶段新增。

表示某个场景下的一条分镜镜头。

```text
镜头序号
景别
机位
镜头运动
画面描述
人物动作
情绪氛围
图像 Prompt
视频 Prompt
负面 Prompt
```

当前数据库还没做这个表，等 PI Agent 分镜能力进入开发时再加。

## 7. 权限与租户隔离

系统按组织隔离数据。

同一个后端可以支持多个团队使用，但每个团队只能看到自己的作品项目、文本版本、解析结果和未来分镜数据。

规则：

```text
1. 创建项目时，organization_id 来自当前登录用户
2. 创建人 created_by 来自当前登录用户
3. 查询项目、文本版本、场景、元素、导出时校验组织归属
4. 跨组织访问返回 404 或 403
5. 管理员默认也只管理自己组织内的数据
```

## 8. Agent 架构设计

自动分镜是一个适合 Agent 的任务，但不要一开始就把所有能力塞进后端。

推荐架构：

```text
React 前端
  -> Java Spring Boot 后端
      -> PostgreSQL
      -> AgentClient 抽象
          -> RuleBasedAgentClient
          -> PiAgentClient
              -> PI Agent 独立服务
```

Java 后端负责：

```text
用户和权限
组织隔离
作品项目
文本版本
场景和元素存储
分镜结果存储
任务状态
接口文档
导出
```

PI Agent 负责：

```text
小说语义理解
场景视觉化
镜头拆分
景别/机位建议
Prompt 生成
连续性检查
风格一致性检查
```

第一版 `AgentClient` 只需要：

```text
analyzeScript()
```

后续再扩展：

```text
generateStoryboard()
generateShotPrompts()
checkContinuity()
```
